# API·BE 협의 메모 (api260504)

**대상:** 백엔드 개발자 전달용  
**작성일:** 2026-05-04  
**FE 저장소:** `-empecs_cgms_fe_app` (Flutter) 최근 반영 기준

본 문서는 **앱 쪽에서 이번에 맞춘 동작·UX**에 대해, BE에서 **확인·보완하면 좋은 계약**만 정리한다. 이미 구현된 엔드포인트가 많으므로 **변경 요청**과 **비변경 확인**을 구분했다.

## 1. 혈당 조회 `GET /api/data/glucose` (우선순위: 중)

**사용처:** 대시보드·PD·Data Share(SC_07) 등. Data Share는 로컬이 비었을 때 **서버 보강** 후 다시 로컬 조회한다.

**앱 변경:** `DataService.fetchGlucose`에 선택 콜백 추가.

- HTTP **200이 아닌 응답** → `onServerNon200(statusCode)` 호출 후 빈 리스트 반환.
- **네트워크/파싱 등 예외**로 서버 GET을 시도한 뒤 실패 → `onServerNetworkError()` 호출.

**BE에 요청:**

1. **4xx/5xx** 시 가능하면 **JSON 본문**에 `message` 또는 `error` 코드를 넣어 달라. (앱은 현재 본문을 파싱해 사용자에게 띄우진 않지만, 로그·추후 UX에 사용.)
2. **401/403** (토큰 만료·권한) vs **404** (기간 내 데이터 없음) vs **500** 구분이 되면, FE에서 메시지 분기하기 쉽다.
3. **200이지만 빈 데이터**는 현재와 동일하게 처리하면 된다. (Data Share는 이 경우 “기간 내 혈당 없음” PDF/CSV로 진행.)

**쿼리:** 기존과 동일 (`from`, `to`, `limit`, `compact=1` 등).

## 2. EQ 등록·시작일 `GET /api/settings/eq-list/resolve` · `POST /api/settings/eq-list` (우선순위: 중)

**배경:** BLE **연결 성공 시** 앱이 로컬 `sensorStartAt`을 **서버 `startAt` 우선**으로 맞추고, 서버 조회 실패 시 **접속 시각(UTC)**으로 채운 뒤 `POST /api/settings/eq-list`로 **업서트**할 수 있다.

**BE에 요청:**

1. **`GET .../resolve`** (`serial` / `bleMac` 쿼리) — 기존 [api_rev_260417a.md](./api_rev_260417a.md) 스펙 유지. `startAt`이 **해당 센서 세션의 정답**이어야 한다.
2. **`POST /api/settings/eq-list`** — `{ "serial", "startAt" }` 업서트가 **멱등**하게 동작하는지 확인 (같은 serial 반복 POST 시 200, 중복 에러 없음).
3. EQ 행에 **bleMac** 저장이 되어 있어야 MAC 기준 resolve·재설치 복구가 안정적이다 (기존 메모와 동일).

## 3. 인증 `POST /api/auth/login` · `POST /api/auth/register` (우선순위: 낮~중)

**앱 변경 요지:** 오프라인 로그인은 **마지막 성공 계정**만 솔트+해시로 검증 (`LocalOfflineAuthStore`). 온라인은 기존대로 서버 우선.

**BE에 요청 (선택):**

1. **Register** — 오프라인 가입 후 온라인에서 재시도 시 **이메일 중복**이면 **409** 등 명확한 코드 + JSON 메시지 권장. (현재 앱은 일부 경로에서 예외를 삼켜 UI에 안 띄울 수 있음 → 추후 개선 시 활용.)
2. **Login** — 재설치 후 동일 이메일 로그인 실패 이슈가 있었다면, **서버 응답 코드·본문**과 앱이 붙는 **API 베이스 URL(스테이징/운영)** 일치 여부를 함께 보면 좋다. (앱 이슈와 BE 이슈 분리 필요.)
